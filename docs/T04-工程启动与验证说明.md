# T04 工程启动与验证说明

日期：2026-10-17。当前交付为React网页和FastAPI服务的工程基础，正式报价数据库、上传、识别、审核、应用和导出仍按T05及后续任务实现。

## 1. 环境与锁文件

- Python 3.12或3.13，本次实际验证3.12.8；`.python-version`默认3.12。
- Node.js 22.12或更新版本，推荐24 LTS；本次实际验证24.15.0。
- uv 0.11.23用于Python依赖同步；未安装时可运行 `python -m pip install uv==0.11.23`。
- Python依赖以根目录 `pyproject.toml`、`uv.lock`为准，使用 `uv sync --frozen`，不通过编辑lock文件更换版本。
- 前端依赖以 `frontend/package.json`、`frontend/package-lock.json`为准，使用 `npm ci`。项目npm配置使用官方registry。

本次核实并锁定FastAPI 0.143.3、Pydantic 2.14.0、pydantic-settings 2.16.0、Uvicorn 0.54.0；开发测试使用httpx2 2.13.1，已有T01核读工具使用Pillow 13.0.0。保留T02已验证的Pydantic版本，避免无意改变生成合同。

前端锁定React/React DOM 19.3.1、Vite 8.3.4、TypeScript 7.0.2、React插件6.1.2；类型依赖和格式化工具也纳入npm锁文件。Starlette由FastAPI依赖解析并锁定，当前测试客户端采用其推荐的httpx2。

前端格式化检查使用 `npm run format:check --prefix frontend`；格式化源码使用 `npm run format --prefix frontend`，不会改写contracts目录中的生成文件。

`backend/requirements-contracts.txt`只保留T02独立合同工具的最小依赖，不是完整应用安装清单。开发应用统一使用uv锁文件。

## 2. Windows首次安装

在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
```

脚本校验Node版本，按两个锁文件安装到项目自己的 `.venv` 和 `frontend/node_modules`。仅在根目录没有 `.env` 时从 `.env.example`复制；已有配置不会覆盖。不会创建SQLite数据库、导入真实报价或重置业务数据。

ExecutionPolicy参数只影响本次PowerShell进程，不修改系统全局策略。也可在已经允许执行本地脚本的终端直接运行 `./scripts/setup.ps1`。

## 3. 开发模式

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev.ps1
```

等待显示 `ASW-SFQS ready` 后打开：

```text
http://127.0.0.1:5173
```

后端在8000、前端在5173，浏览器所有API请求使用相对路径 `/api/v1/...`。Vite将 `/api` 转发到本机后端，不配置跨源通配CORS。前端源码及共用生成类型之外的目录不在Vite文件服务允许范围内。

开发管理器只启动并管理自己的两个子进程；日志写在 `data/logs/backend.log`、`data/logs/frontend.log`。Ctrl+C停止两者，实际检查8000和5173端口均释放。端口已占用时直接说明错误，不按端口查找并强杀其他进程。某个子进程异常退出或启动超时，会清理另一个已启动的子进程。

后端不使用reload子进程：修改后端Python文件后，Ctrl+C停止并重新启动开发模式。前端有Vite热更新。

## 4. 构建后的单地址模式

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local.ps1
```

打开：

```text
http://127.0.0.1:8000
```

构建脚本检查共用合同是否过期、执行TypeScript检查和Vite构建。启动脚本将当前服务环境设为local，同一个FastAPI进程提供HTML、`/assets`和API。没有 `frontend/dist/index.html`时拒绝启动并提示先构建，不显示假成功的空白页面。

Ctrl+C停止服务。更新前端代码后需重新构建并刷新页面；服务重启会使旧进程签名的本机会话失效，点击“检查连接”或“重试连接”会重新建立有效会话。

开发模式和单地址模式默认使用同一个后端8000端口，切换时先停止前一种模式。

## 5. 配置

后端优先级为显式初始化参数、进程环境变量、`.env.local`、`.env`、默认值。启动脚本根据模式设置APP_ENV，端口和其余配置正常读取。Vite的两个端口由APP_PORT、FRONTEND_PORT读取；开发管理器把后端最终读取的端口显式传给Vite，保持一致。

| 字段 | 默认值/语义 |
|---|---|
| APP_ENV | development；单地址脚本临时设置local |
| APP_HOST | 只允许127.0.0.1；不支持直接改为0.0.0.0或局域网地址 |
| APP_PORT | 8000，范围1024—65535 |
| FRONTEND_PORT | 5173，必须不同于APP_PORT |
| APP_TIMEZONE | Asia/Shanghai |
| STORAGE_ROOT | 项目data目录；相对路径按项目根目录解析 |
| DATABASE_URL | 本机SQLite配置预留，T04不建表、不连接报价数据库 |
| MODEL_PROVIDER / MODEL_NAME / MODEL_BASE_URL / MODEL_API_KEY | 默认均为空，只在服务端读取 |

模型配置不作为启动前置。未填写时状态NOT_CONFIGURED；即使填了provider/model/key，T04也只返回ADAPTER_NOT_IMPLEMENTED，不能声称已经成功连接模型或可识别报价。MODEL_BASE_URL和密钥不返回浏览器，不允许使用VITE_前缀保存密钥。

## 6. 已实现接口和合同边界

| 接口 | 实际行为 |
|---|---|
| GET /api/v1/health | 服务存活、应用版本、当前阶段、数据库未初始化及模型配置状态 |
| GET /api/v1/bootstrap | 从T03带hash的公开种子读取六区域摘要、每区域前6个目的地，建立/复用本机会话并返回对应CSRF令牌 |
| POST /api/v1/session/verify | 检查当前会话；不会写入业务数据 |
| GET /api/v1/openapi.json | 运行服务的实际OpenAPI，只列出已实现业务路径 |

`contracts/openapi.json`保留T02的计划业务接口，同时新增上述系统合同，使用 `x-implemented`区分实际实现与计划接口。不能拿合同中尚未实现的candidates/exports等路径宣称正式更新服务已经完成。

响应结构和前端类型仍由 `backend/app/domain/contracts.py`统一生成，前端直接导入 `contracts/generated/contracts.ts`。新增403 FORBIDDEN、405 METHOD_NOT_ALLOWED错误码；错误仍使用统一error包和X-Request-ID。候选、计划等后续写操作也必须经过同样的本机请求边界。

运行端的会话接口在OpenAPI中声明Origin、X-CSRF-Token和本机会话cookie，真实请求也在后端校验，不依赖前端隐藏按钮。

## 7. 本机访问边界

后端绑定127.0.0.1，检查准确Host及其端口、Origin、跨站Fetch Metadata。写请求额外要求HttpOnly/SameSite=Strict签名会话cookie和与该cookie绑定的CSRF令牌；缺失、不匹配、伪造或跨站请求返回403。没有放开 `Access-Control-Allow-Origin: *`。

会话不是企业登录系统，不能用作开放局域网的认证。签名密钥仅在当前服务进程内生成，不下发浏览器；CSRF令牌只属于当前会话，不是模型密钥。所有响应含请求追踪ID与no-store，错误不回显提交的敏感值和异常堆栈。

静态服务仅开放构建页面和assets，没有把项目根目录、data、原件或私有样本挂成文件站点。后续上传、下载和导出接口仍须在T18/T31增加逐文件授权和资源限制，不能认为基础边界已经替代全部文件访问设计。

## 8. 当前页面范围

- 五个导航入口可切换：报价总表、上传报价资料、审核工作台、变更与导出、报价查询。
- 六区域标签和目的地数量来自实际API读到的T03无价种子；可切换并查看每区域前6个目的地。
- 当前“报价总表”是目录预览，正式数据库明确显示待接入；价格显示破折号，不表示零运价。
- 上传、审核、查询、更新和导出按钮明确标记尚未启用，不调用模拟成功接口。
- 页面加载、服务中断和连接重试有真实状态；实际测试过停止服务后显示错误、重启后点击重试恢复。

完整目的地检索、表格编辑、分页和正式报价API仍分别属于T09/T10等后续任务，不在T04提前装作完成。

## 9. 验证命令

```powershell
uv run --frozen python -m unittest discover -s tests/system -v
uv run --frozen python -m unittest discover -s tests/contracts -v
uv run --frozen python -m unittest discover -s tests/template_assets -v
uv run --frozen python contracts/generate.py --check
```

有本机私有样本时另运行：

```powershell
uv run --frozen python tests/fixtures/tools/validate_t01.py
uv run --frozen python tools/template_assets/build_t03.py --check
```

服务已启动后：

```powershell
uv run --frozen python scripts/smoke.py --expect-frontend
```

该冒烟工具只接受loopback HTTP地址，不需要真实报价或模型密钥，检查实际HTML、构建资源、API、同源会话和私有路径拒绝访问。开发代理可通过 `--base-url http://127.0.0.1:5173`检查；同时需要预览构建资源时使用单地址模式8000。

Windows受限沙箱可能禁止Python安全临时目录或Vite原生构建子进程；本次最终测试在普通Windows进程权限下通过，不把沙箱内的权限错误当作应用通过。未做OCR、正式数据库迁移、报价入库或实际Excel导出验收。
