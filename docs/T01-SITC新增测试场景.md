# T01补充：SITC样本的新增测试场景

> 公开版：金额示例已经脱敏，仅用于开发说明；真实费率和精确校验值保存在本地私有资料中。

日期：2026-10-17。来源是用户提供的SITC海丰报价图片，冻结于`tests/fixtures/private/t01-v1/raw/`。本文是基准场景，不代表已批准将SITC报价导入正式库，也不替用户决定G/R价格的用途。

原开发文档的50条验收继续保留；下列场景补充覆盖第三份真实报价来源，在T02确定数据契约时纳入测试设计。

| 编号 | 来源事实/场景 | 应有行为 |
|---|---|---|
| S01 | 图中有左侧报价、G大客户结算、R报价、R结算 | 分别保存为四个价格口径，不按同港重复价删除，也不挑最低价 |
| S02 | 左侧20GP和40GP/HC有明确列名 | 记录原列与柜型关系；40GP与40HQ同值需记录本列依据；黄色列不因相邻而无提示套用柜型 |
| S03 | 图片有SITC船司名称，但没有明确青岛起运字样 | carrier可识别SITC；POL仍待明确，不能因为导入青岛系统就当源图明示青岛 |
| S04 | 时效表头明确“ETD”，日期10.26—11.1，标题2026 | 保留跨月完整日期与ETD依据，年份来源是标题；不是UNSPECIFIED，也不是上传日 |
| S05 | 大阪、HPH、DAD、LCH等引用地点加附加金额，精确数值见私有样本 | 保留引用地点和附加金额，不当普通数字；基价需同价格口径、服务、币种、柜型和有效期，未确认不计算 |
| S06 | 同一行列出大阪/神户、博多/门司等 | 按目的地展开，保留共同来源；不要把同一个视觉行只识别为一个港 |
| S07 | 泰国CKV2与VTX5两组同港、航程和运输方式不同 | 保留不同服务方案，不能因为价格相同就删除其中一条 |
| S08 | 胡志明CAT LAI、PHUOC AN分别列出 | 码头身份独立；同城同价也不合并 |
| S09 | 仰光AWPT与MITT价格及运输方式不同 | 独立终端方案；不能都挂到泛仰光后互相覆盖 |
| S10 | LSS有USD，主运价未明确币种 | 主价币种保留未知；LSS和基础价分开，不默认全部都是USD |
| S11 | “含BY”“含”“含LSS”“不含” | 保留原文费用口径；含哪些费用不明时不展开解释，不据此标为全包价 |
| S12 | 釜山原价1/1、仙台G列1/1 | 保留可读的1，不变成0/空白或自动补成较大价格；提示核对 |
| S13 | 航程2/3、1/4、11/17 | 保存为备选或待绑定数据，不能一律变为连续区间或承诺航程；服务/目的地对应未明确时不猜 |
| S14 | 班期“周三/六PQS/周日PTK” | 可提议周三、周六、周日，但保留原串，服务与日期绑定不能错配 |
| S15 | R列80/111等合写价格、部分空白/-- | 保存原始双值及柜型待确认；空白和--不变0，也不无依据复制其他口径价格 |
| S16 | 菲律宾、越南、印度等有不同LSS支付方式及重量限制 | 按来源块/行关联，默认到付与必须预付不能混用；超重费不自动相加 |
| S17 | 印度块含Nepal(Birgunj)目的地 | 标记国别继承冲突，不能把尼泊尔直接确认为印度；实际国家和业务航线分别审核 |
| S18 | 64视觉行展开75条目的地/服务记录 | 展开、价格口径、服务分支分别统计，不把75条等同75个唯一港口或75条可直接应用报价 |

这些场景应先通过固定人工标注的结构/业务测试，再评价模型对原图的实际提取结果。当前T01校验只证明资料和标注包一致，不证明OCR已经实现。
